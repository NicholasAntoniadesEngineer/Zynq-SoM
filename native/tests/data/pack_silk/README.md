# Silkscreen kernel float-parity handoff

## Fix and ownership

Only `native/src/pack.cpp` changes production logic. No public API, PCB placement
source, emission source, Python adapter, shared build, CMake, module, CLI, or
commit was changed by this follow-up. No overlapping Aristotle placement edit is
needed. The parent owns integration and commits.

The compiler contracted the width expression `n * size + thick` into one
multiply-add. For a six-character label at size 0.8, Python rounds the product
first and gets width 4.920000000000001. The old kernel selected x =
171.71300000000002 instead of Python's 171.713. This is not just cosmetic:
an exact board boundary can select a different ring/orbit candidate.

The source-local `silk_product` helper materializes a binary64 product before its
following addition/subtraction, using a standard C++ volatile double. It is used
only for text widths, orbital label coordinates, and the final refdes rotation.
Candidate order, bounds, penalties, tie breaking, shrinking, and rounding policy
are unchanged. No epsilon, output snap, oracle bypass, or build-flag dependency
was introduced. Other packing kernels retain their original arithmetic.

original emitter at commit `9f1fe2a4`, including all 2,263 occupied and 103 already
placed boxes. Its `old_cpp` is diagnostic evidence, never expected output.

- the captured real case and a no-obstacle minimal reproduction;
- lower/upper exact-boundary cases that change which candidate is selected;
- 20 text extents at five sizes and four string lengths;
- empty, occupied, paired, bounded, fully blocked, and off-board label searches;
- a narrow window verified to force an orbital candidate;
- real carrier refdes relocation/shrinking at rotations 0, 90, and 37 degrees.

`_place_refdes_py`. During refdes capture its nested label call was explicitly
redirected to `_place_clear_label_py`, not the native dispatcher. Expectations
are frozen bytes, never regenerated by the C++ test. The runner checks exact
values (including signed zero), schema, case count, and scalar count.

## Parent integration

`src/pack.cpp` is already in `schgen_core`; no new production source or compile
option is required. Add only this native regression target/test:

```cmake
add_executable(schgen_pack_silk_contracts tests/pack_silk_contracts.cpp)
target_link_libraries(schgen_pack_silk_contracts PRIVATE schgen_core)
target_compile_options(schgen_pack_silk_contracts PRIVATE
    -Wall -Wextra -Wpedantic -Werror -ffp-contract=off)
add_test(NAME native_pack_silk_contracts COMMAND schgen_pack_silk_contracts
    "${CMAKE_CURRENT_SOURCE_DIR}/tests/data/pack_silk/cases.json")
```

From the repository root, check fixture integrity and compile an isolated
executable. Passing the updated `pack.cpp` before the archive ensures the archive's
old pack object is not used:

```sh
(cd native/tests/data/pack_silk && shasum -a 256 -c SHA256SUMS)
silk_build=$(mktemp -d /private/tmp/pack-silk-contracts.XXXXXX)
clang++ -std=c++17 -Wall -Wextra -Wpedantic -Werror -ffp-contract=off \
  -mmacosx-version-min=26.6 -O3 -I native/include \
  native/src/pack.cpp native/tests/pack_silk_contracts.cpp \
  native/build/libschgen_core.a -lxml2 -pthread -o "$silk_build/contracts"
"$silk_build/contracts" native/tests/data/pack_silk/cases.json
```

Also repeat with `-ffp-contract=fast` and with the flag omitted: both must pass.
For ASan+UBSan, use:

```sh
clang++ -std=c++17 -Wall -Wextra -Wpedantic -Werror -ffp-contract=off \
  -mmacosx-version-min=26.6 -O1 -g -fsanitize=address,undefined \
  -fno-omit-frame-pointer -I native/include \
  native/src/pack.cpp native/src/json.cpp native/src/occupancy.cpp \
  native/src/seat.cpp native/src/turn.cpp native/src/quantize.cpp \
  native/tests/pack_silk_contracts.cpp native/build/libschgen_core.a \
  -lxml2 -pthread -Wl,-map,"$silk_build/asan-link-map.txt" \
  -o "$silk_build/contracts-asan"
ASAN_OPTIONS=halt_on_error=1 UBSAN_OPTIONS=halt_on_error=1 \
  "$silk_build/contracts-asan" native/tests/data/pack_silk/cases.json
```

The deployment target matches the supplied macOS archive; omit it for Linux.
The sanitizer link map contains no uninstrumented project archive objects.

## Observed validation

Artifacts are in `/private/tmp/pcb-silk-trace.SCMTzA`.

- Old archived kernel: **20 / 181 fields fail**, including both candidate-selection
  boundary regressions. Unchanged source compiled with contraction off: **0 fail**.
- Updated kernel, strict C++17, optimized default and aggressive contraction:
  **181 exact fields, 0 mismatches**.
- Updated kernel under ASan+UBSan: **181 exact fields, 0 mismatches**.
- Updated kernel linked into live native emission: **473 checks pass**, including
  two real projects and all 50 mutations with exact frozen PCB/project/rules bytes.
  The same **473 checks pass under full ASan+UBSan**, with the complete linked
  project-source closure instrumented; see `emission-asan-link-map.txt`.
- Original Python emitter with native trace enabled and the three fixed kernels
  injected from an isolated C++ library: **carrier and devkit_mini pass**, with
  exact frozen PCB bytes; 87 text, 590 label, and 523 refdes calls. The original
  Python trace assertions remained enabled and unchanged. No shared module was
  replaced. The isolated library was built with `-O3 -ffp-contract=fast`.

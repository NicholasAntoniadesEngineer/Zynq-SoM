# Native PCB verification contracts

These 16 report fixtures were copied, before running the native implementation,
from the existing `carrier/reports` and `devkit_mini/reports` artifacts. They are
independent expectations, not outputs regenerated by the code under test.
The contracts never invoke Python or write a hardware/project/build artifact.

`native/tests/pcb_checks_contracts.cpp` accepts the repository root as its sole
argument. It reads each project's actual PCB, escape artifact, SoM interface,
mapping, sheet index, and canonical circuit JSON. It resolves repository and
installed KiCad footprints once per source, then shares immutable snapshots.
The supported KiCad footprint roots are the standard macOS application path,
`/usr/share/kicad/footprints`, and `/usr/local/share/kicad/footprints`. Missing
inputs fail the test; there is no skipped-project or success fallback.

Eight complete reports per project are compared byte for byte. The return-path
fixture includes the command's explanatory preamble, which the pure result does
not own; the complete gate summary after that preamble is compared. Refdes has
no source summary method, so its typed counts, pairs, and enforcement behavior
are tested directly.

The baseline deliberately retains RETURN-PATH **FAIL**: 69 pairs, 138 contacts,
29 failures, worst distance 4. RETURN-STITCH separately covers all 29 failing
contacts with seven actual emitted vias, worst distance 1.4819 mm. It quotes the
unchanged failing v1 summary. The tests never convert one verdict into the other.

PCB reconstruction in the test is intentionally independent of the new gates:

- Every numbered source pad is booked, including NC entries with net `(0, "")`,
  because the source model counts these while emitted PCB net clauses omit them.
- The emitted PCB has locked escape copper but does not retain `group`, `conn`,
  or `role` metadata. The test associates locked copper with its nearest actual
  DF40 and marks a segment as a stub only when its endpoint copper touches an
  actual GND pad. Paired stubs straddle two pad columns. No copper is synthesized.
- Module-core coordinates are fixed fixture inputs. Curated triage is resolved
  from project mappings and explicit recognized fixture signal families;
  unknown fixture functions throw. Neither is inferred from native output.

Real-project mutations remove vias, spines, emitted nodes, or the canonical
plane; alter copper nets and hashes; move a DF40; damage genuine pair records;
place a via in foreign pad copper or outside the plane; remove interface GND
contacts; overload delivery rails; reverse connectors; rotate a model; stack
connectors; collide actual refdes; and crowd an actual IC with a foreign part.
Synthetic contracts exercise return-row topology, missing inputs, all allowed
model rotations, tier/exclusion and ratchet behavior, hidden/bottom refs,
overmold thresholds, lane order/clearance, and SHA-256 standard test vectors.

The public boundary is `native/include/schgen/pcb_checks.hpp`. All gate functions
are pure. `PcbCheckInput` owns an immutable prepared model snapshot; construct a
new one after changing poses. Footprint pointers remain shareable. File loading,
publication, ratchet persistence, CLI policy, and transport belong to callers.
`check_connector_models` also accepts unresolved footprints, retaining the
original informational missing-model result. Preparation records unresolved
geometry explicitly; checked `geometry_at`, `courtyard_at`, and `pad_bbox_at`
accessors refuse to invent it when a gate actually needs it. Spacing only
requires connector geometry. Mechanical only requires every courtyard when
checking a supplied SoM core, and fanout retains its original eager requirement
for every courtyard. Isolated missing-footprint contracts cover these cases.

The escape hash uses the explicitly supplied interface bytes, the exact supplied
footprint bytes, poses, and original fixed constants. This removes the source
function's hidden carrier-path read while retaining the existing carrier and
devkit content keys. Return-stitch takes the already-computed return-path result
and curated classes, so it does not reload or rescan the SoM interface.
